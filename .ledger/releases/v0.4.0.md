# Ledger v0.4.0

## Summary

The 0.4 foundation from decision D005. Every command is now generated from one
operation registry, source records are served from an incremental catalog
cache, and every file-oriented surface shares one retrieval contract. This is
the base the 0.5 engine server builds on.

## Public Notes

- Every command except `serve` and `mcp` now supports `--json` and returns
  the versioned machine envelope, including `init`, `new`, `feedback`,
  `index`, `agents`, and the `docs` subcommands.
- The MCP server grew from 8 tools to 18, each with input and output schemas,
  read-only annotations, and structured content. The original 8 keep their
  names, inputs, and summaries.
- Repeated commands and agent calls parse only the records that changed. A
  catalog cache under `.ledger/cache/` (JSON everywhere, built-in sqlite on
  Node 24.15 or newer) cut warm reads on this repository from 38 ms to 4 ms.
  New commands: `ledger cache status`, `ledger cache warm`,
  `ledger cache clear`.
- `ledger explain`, `ledger conflict`, and `ledger packet` agree on which
  records match a path and now include the decisions, backlog items, and
  superseding records one hop away. Packets carry related records within the
  token budget, and `graph.json` gains `supersedes` edges.
- `ledger doctor` fails, rather than warns, when the rendered reader is over
  its size budget.
- Library: `ledgerOperations`, `buildOperationsContract`,
  `retrieveByPath`, `matchFilePath`, and `relatedRecords` are exported
  from the package root; `explain` JSON data now carries `records`,
  `related`, and `missing`.

## Known Issues

- Automatic sqlite selection waits for Node 24.15; earlier Node 24 lines use
  the JSON backend unless `cache.backend: sqlite` is set explicitly.
- The unreleased `context` field that `explain --json` briefly carried on
  master between milestones is replaced by `records`.
