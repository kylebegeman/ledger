# Ledger v0.5.0

## Summary

The engine server from decision D005. `ledger serve --api` turns Ledger into a
local memory engine: one loopback process with a JSON API, an event stream,
live reload, and MCP over HTTP, and CLI commands delegate to its warm cache.

## Public Notes

- `ledger serve --api` starts the engine: the reader plus a JSON API at
  `/api/v1` (every workspace operation as `POST /api/v1/operations/<name>`
  with the same machine envelope as `--json` and the exit code in a
  `Ledger-Exit-Code` header), a server-sent event stream at `/events`, MCP
  over Streamable HTTP at `/mcp`, and a server card at
  `/.well-known/mcp/server-card.json`. The same loopback and token hardening
  as `ledger serve` applies.
- While the engine runs, CLI commands in the same project delegate to it and
  answer from its warm cache with identical output and exit codes. Pass
  `--local` or set `LEDGER_NO_DAEMON=1` to run in-process; a stale or missing
  engine falls back automatically. `ledger doctor` reports the engine state.
- The reader reloads itself after every rebuild when served by the engine and
  keeps its URL state; a failed rebuild keeps the last good render.
- MCP hosts get resources (`ledger://records/{id}`, `ledger://packet/{path}`,
  `ledger://contract`) and prompts (`ledger_agent_instructions`,
  `ledger_handoff`) over both stdio and HTTP.
- Search scoring lives once and is shared by `ledger search` and the reader,
  so terminal and browser rankings match exactly.
- Recursive watching survives Windows short-name paths.
