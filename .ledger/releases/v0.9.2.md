# Ledger v0.9.2

## Summary

Records can be written whole from any surface, and the reader now follows
records to the files, symbols, and records they name. This release adds:

- section bodies for every authoring command, and `ledger update`
- `ledger context`, a review packet for a change set
- `ledger doctor --fix`, and a health check for installed hooks
- symbols for Go, Rust, Python, and Swift
- entity views, backlinks, copy buttons, and changed-since-last-visit
  markers in the reader
- an Atom feed, release permalinks, and page metadata for the public
  changelog
- a generated command reference

## Public Notes

- `ledger new`, `feedback`, `backlog new`, `decision new`, and `promote` take section bodies with `--section Heading=text` and `--sections-file`, and the JSON API and MCP take them as `sections`. `ledger new` also takes `--file`, `--doc`, `--symbol`, `--related`, `--decision`, `--backlog`, and a docs impact declaration, so one command can write a receipt that passes `ledger ready`.
- `ledger update <id>` changes a record in place: its title and heading, status, list fields, docs impact, or sections. A list flag replaces that whole list. Over MCP it is `ledger_update`, which asks the user to confirm first.
- The MCP tools that write records now check the call before asking, so the user is never asked to confirm a call that would fail, and the confirmation names the sections a call writes.
- `ledger context` prints one review packet for the working tree, the staged diff, or a `--base` and `--head` range. For each changed file it gives coverage, docs impact, and the newest records that mention it with their invariants and conflict rules, and it lists the change's receipts with their verification. It fits a token budget, and it is also the `ledger_context` MCP tool and an API route.
- `ledger doctor` checks installed Claude Code, Codex, and Cursor hooks. It warns when a hook runs a command other than `agents.command`, or when that command fails or reports a different Ledger, because hosts skip failing hooks without a message. `ledger doctor --fix` first repairs interrupted writes, a stale lock or engine record, a stale cache, stale indexes, and a missing reader, and never edits records.
- Drafts, hook drafts, and `ledger stale` read Go, Rust, Python, and Swift declarations, with methods and members named `Type.member`, or `Type::member` in Rust. A draft names the method a diff touched rather than the whole type, and `ledger doctor` says which languages are outlined. No toolchain or new dependency is needed.
- In the internal reader, a record's files, patterns, and symbols open a list of every record that names them. Its relationships open the linked records, and a Referenced by list shows the records that link to it. The views have their own URLs and work from a `file:` URL.
- The reader's command palette suggests matching files, symbols, and areas before records. Typing right after opening it keeps every character.
- The record panel copies the record's link, its source path, the `ledger packet` command for it, and its agent-ready context.
- Both reader profiles mark records that are new or changed since your last visit and can list only those. The state stays in your browser.
- Row and panel summaries read as plain prose, without list or bold markers.
- `ledger render --profile public` also writes `feed.xml`, an Atom feed of the newest 50 releases, and gives each release a permalink such as `#v0.9.2`. Both profiles carry a description, Open Graph tags, and an icon. `--site-url` makes the canonical link and the feed's links absolute. `docs/PUBLISHING.md` has a GitHub Pages workflow.
- `docs/COMMANDS.md` lists every command's usage, help, and flags, generated from the same registry as `ledger help`.
- The reader's embedded script and stylesheet are minified, and detail chunks are smaller, which offsets the new features' size.
