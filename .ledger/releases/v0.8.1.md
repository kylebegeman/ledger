# Ledger v0.8.1

## Summary

Fixes from an audit of 0.8.0. Hooks for parallel tool calls keep every
edited path, a `.ledger/` inside a repository subdirectory drafts receipts and
checks coverage for its own files, and every new draft is announced. The
reader ranks search exactly like `ledger search` and its palette works from
disk. `verify --run` bounds environment variables, and `adopt` proposes only
read-only checks.

## Public Notes

- Hooks no longer lose edits when an agent changes several files at once. The workspace write lock waits briefly for another Ledger process instead of failing, and a hook whose record changed while it waited re-reads and retries, so every edited path reaches the session record and its draft.
- Ledger works from a directory inside a Git repository, such as `packages/app/.ledger`. Changed paths from Git are made relative to that directory, so hook drafts, `coverage`, `docs impact`, `verify`, and `new --from-diff` see the project's own files.
- A draft the hooks create is always announced on the next prompt, even when it reuses the id of a draft you deleted. `ledger cache clear` now also removes the notice store, which forgets sessions that no longer exist.
- `ledger hooks install` keeps a command you added to Ledger's own hook group instead of adding a second Ledger group, and `ledger agents --write` replaces every managed block so a file never carries two versions.
- Hook drafts from wide diffs stay readable: the default title names at most three areas, drafts keep the eight most touched areas, and symbols are capped. Codex `apply_patch` edits sent as an argument list are recorded, and a hook payload without a session id is ignored with a message instead of filed under another session.
- Hook and authoring edits keep a record's line endings, so session records on Windows checkouts stay CRLF.
- The reader ranks search results exactly as `ledger search` does; before, it ignored part of each record's text and dropped matches. Opened from disk, the command palette lists and filters records instead of staying empty, and command-click on a record opens it in a new tab.
- Inline code in the reader shows a visible chip in the light theme, a summary that is one long code span keeps its text, and code spans are found in linear time.
- `ledger verify --run` matches environment assignments as part of the allowlisted command. A Verification bullet such as `LEDGER_UPDATE_CONTRACT=1 npx vitest run` runs only when `verification.allow` lists that assignment, and one that sets `NODE_OPTIONS` or `PATH` without a matching pattern is skipped.
- Only change entries cover a path. Under `git.coverage: any`, session records, backlog items, and decisions no longer satisfy coverage, which now matches docs impact, and `ledger ci` messages no longer say "in this change set" under `any`. A `docsImpact` declaration whose reason is still a TODO never counts as evidence, whatever its status. The docs impact JSON field `historicalFiles` is now `earlierEvidenceFiles`.
- `ledger adopt` ignores `vendor/` at any depth and never makes it a coverage root, ignores build output inside packages, and leaves Make targets and npm scripts that reset, migrate, format, serve, start, or watch out of the proposed allowlist, which lists at most 40 npm scripts.
- `ledger docs reconcile` refuses a routing path it cannot read, such as a directory or symlink, even with `--force`, and says why.
- The release workflow takes the GitHub Release notes from `ledger release notes`.
