# Ledger v0.8.0

## Summary

Adoption. Fixes from Ledger's first outside adoption, in Kore: agents are
told about the receipt the hooks drafted for them, one configured command runs
Ledger in every hook and instruction, `adopt` infers its configuration from
the tracked tree, `docs reconcile` never overwrites curated routing files, and
linked session records survive pruning. The README now shows the product with
real output, and Ledger has a new mark. Checking that README against the code
turned up four more fixes: `git.coverage: any` now relaxes docs impact in
`ledger ci`, the GitHub Action keeps one pull request comment, `verify --run`
accepts commands written with `agents.command`, and the reader renders inline
code.

## Public Notes

- Agents now hear about the receipt the hooks drafted for them. A new `user-prompt-submit` hook for Claude Code and Codex names the draft once on the next prompt, and session start lists every receipt the session links, so the agent finishes the draft instead of creating another. Landing a receipt mid-session no longer produces a second draft. Re-run `ledger hooks install` to add the hook; Codex asks you to approve the hooks again.
- `agents.command` in `.ledger/config.yaml` sets the one command that runs Ledger in a repository, such as `npx ledger` or a pinned `npx --yes @kylebegeman/ledger@0.8.0`. `ledger hooks install --command` saves it, and the hooks, the `AGENTS.md` block, the skill, and the context the hooks inject all use it. For Claude Code, `--import-agents` adds the `@AGENTS.md` import to `CLAUDE.md`.
- `ledger adopt` reads the tracked tree and writes a configuration that fits it: coverage roots for the tracked top-level directories, ignores for generated code such as templ and sqlc output, a proposed `verification.allow` from the detected toolchain with release and deploy targets left out, and `git.coverage: any`. `ledger init` and `ledger adopt` also add a marked block to `.gitignore` for Ledger's derived files.
- `ledger docs reconcile` no longer overwrites routing files Ledger did not generate. It explains the refusal and exits 1 unless `--force` is passed, and `ledger adopt` points `docs.routing` under `.ledger/` when curated routing files exist. A `START_HERE.md` from an older `init` that never ran reconcile needs `--force` once.
- `ledger session prune --write` keeps expired sessions that another record links and closes them instead of deleting them; session records are meant to be committed. An active session past its expiry, such as a Claude desktop tab closed with `/exit`, stops collecting edits, and the next session keeps its linked receipts.
- Hook drafts no longer list session records or templates, start with a neutral `Changes to <areas>` title that `ledger ready` asks the agent to replace, and record edits Codex makes with `apply_patch`.
- Hooks no longer draft a duplicate of a receipt you wrote yourself. A receipt that is new or modified in the working tree covers its files like one the session links, a link named in either record counts, and only touched files that still differ from `HEAD` are pending, so a receipt written with `ledger new` or already committed is respected.
- `ledger verify --run` understands `agents.command`. A Verification command written with it, such as `npx ledger validate` or a pinned `npx --yes @kylebegeman/ledger@0.8.0 ready`, matches the same `ledger` pattern in `verification.allow`, and a bare `ledger` command runs through the configured command instead of whatever `ledger` is on the PATH.
- Docs impact follows `git.coverage`. Under `any`, a changed source file can take its evidence from an earlier receipt that lists it with a reviewed `docsImpact` declaration or docs references, so `ledger ci` judges coverage and docs impact under one mode, and adopted repositories stop failing on files their receipts already cover. The docs impact output lists those files under `historicalFiles`. Repositories on `current` see no change.
- With `comment: "true"`, the GitHub Action keeps one Ledger comment on a pull request and updates it on later runs instead of posting a new one. Pull requests from forks get a notice instead of a failed step, and a failed GitHub API call is a warning.
- The reader renders Markdown code spans in summaries, invariants, verification, and release notes as inline code instead of showing backticks. Record text is escaped first, so a code span never becomes markup.
- `ledger stale` and `ledger doctor` no longer fail when a receipt lists a screenshot or another file that is not UTF-8 text; anchors and symbols are checked against the text files it lists.
- The reader no longer logs an `InvalidStateError` in the browser console when the browser skips a view transition, as it does in a background tab; the list still updates.
- `ledger doctor` no longer asks for the TypeScript parser in repositories with no TypeScript or JavaScript under coverage.
- The README shows the reader, the context agents receive, and the checks with real command output. Ledger has a new emerald mark, and the reader's accent color follows it.
