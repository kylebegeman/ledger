# Ledger v0.9.3

## Summary

Codex hooks can now keep their approval across Ledger versions.
`ledger hooks install --host codex --launcher` makes the hooks run a
generated script that holds the pinned command. A version bump rewrites only
that script, so `.codex/hooks.json` stays the same, and Codex keeps running
the hooks without asking again. This release also fixes the advice
`ledger doctor` gives about symbols in repositories that are not TypeScript.

## Public Notes

- `ledger hooks install --host codex --launcher` writes Codex hooks that run `node .ledger/bin/ledger.mjs`, plus that script, which runs your `agents.command`. Codex approves hooks by their definition, so later installs with a new `--command` rewrite only the script and Codex keeps the approval. Start Codex at the project root so the hooks find the script. Later installs keep the form the hook file already uses, and `--launcher=false` switches back and removes the script.
- `ledger doctor` accepts hooks that run the launcher, and warns when the script is missing, runs a different command, or is out of date.
- When no tracked file matches `git.requireEntryFor`, the doctor symbols check names those patterns instead of suggesting the TypeScript parser. When TypeScript sits beside Go, Rust, Python, or Swift, its message says those symbols come from Ledger's outlines and need nothing installed.
