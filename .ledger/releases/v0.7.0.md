# Ledger v0.7.0

## Summary

Trust. Records now carry proof: a pull request needs its own receipt, docs
impact is judged per file, verification commands run and leave evidence, stale
anchors are detected against the code, and CI annotates pull requests. The
reader runtime is typed, bundled, and browser-tested, the engine has a typed
client, and large catalogs stay under their render budgets.

## Public Notes

- Coverage is now bound to the change set. Under the new default `git.coverage: current`, a changed source file must be listed by a change entry that is itself part of the pull request or working tree; files covered only by older records are reported as `historical`. Set `git.coverage: any` or pass `ledger coverage --mode any` while adopting Ledger on a repository with history.
- Docs impact is judged per source file: each changed file needs a change entry in the same change set that lists it and declares docs impact or references docs. A docs edit elsewhere no longer clears every file.
- `ledger verify --run` executes the backticked commands in change entries' Verification sections that match `verification.allow`, and records command, exit status, duration, and commit in `.ledger/reports/evidence.json`. `doctor`, `stale`, `explain`, `packet`, and the reader show whether evidence is fresh, stale, or failed.
- `ledger stale` checks Changed Files anchors and the invariants that cite them against the current code, reporting `stale-anchor` and `stale-invariant`. Write anchors in backticks; `ledger new --from-diff` now drafts them that way.
- `ledger ci --github` prints pull request annotations and a job summary, and the repository's composite action runs it: `uses: kylebegeman/ledger@v0.7.0`.
- `createLedgerClient` and `connectLedgerClient` give TypeScript callers a client for `ledger serve --api` whose operation names and inputs are checked at compile time against the registry.
- The reader's browser runtime is now a typed module bundled with esbuild and tested in a browser environment. Large catalogs shard the search index, split the graph, and move record details into lazily loaded chunks when the page would exceed its budget; small catalogs keep working fully offline.
- `ledger search --full-text` narrows candidates with sqlite FTS5 on large catalogs. Default search is unchanged and identical on every cache backend.
- Symbol extraction reports which extractor ran. `typescript` is an optional peer dependency: install it for parser-backed anchors, otherwise a regex fallback runs and `ledger new` and `ledger doctor` say so.
