# Ledger v0.9.1

## Summary

Agents can write records over MCP, with your confirmation. Ledger's MCP
server moves to version 2 of the MCP TypeScript SDK and speaks protocol
revision 2026-07-28 alongside the 2025 revisions. Over MCP, agents can now:

- create change entries, product notes, backlog items, and decision records
- promote records
- start, note, and close session records

Each write waits for the user to confirm it. A production install drops
from 94 packages to 7.

## Public Notes

- `ledger mcp` and the engine's `/mcp` speak MCP 2026-07-28 and the 2025 revisions from the same tools, resources, and prompts. Clients on the 2025 revisions keep working.
- New MCP tools write records: `ledger_new`, `ledger_feedback`, `ledger_backlog_new`, `ledger_decision_new`, `ledger_promote`, `ledger_session_start`, `ledger_session_note`, and `ledger_session_close`. Each one asks the user to confirm first, naming the action and the project. It writes nothing unless the user accepts with the box checked. A confirmation covers only the exact call it was asked for and expires after ten minutes.
- A declined confirmation returns `confirmation-declined`. A client that cannot show one gets `confirmation-unavailable` before anything is asked. Neither writes anything.
- Over the engine's HTTP endpoint, only 2026-07-28 clients get the write tools, and those tools write only to the engine's own project. 2025-era clients can confirm over `ledger mcp` when they support elicitation.
- On protocol 2026-07-28, the tool, prompt, and template lists carry one-hour cache hints, and the engine notifies subscribed clients when records change.
- Ledger depends on `@modelcontextprotocol/server` and `@modelcontextprotocol/node` instead of `@modelcontextprotocol/sdk`, so a production install is 7 packages instead of 94.
- `createLedgerMcpHttpHandler` and `serveLedgerMcpStdio` join the library's exports. `listLedgerMcpTools` and the operations contract mark the tools that ask for confirmation.
- On `/mcp`, GET and DELETE now answer 405. Before, GET opened an event stream that never carried a message, and DELETE answered 200 without doing anything.
- `ledger hooks install --host codex` now says where to trust the hooks: `/hooks` in the Codex CLI, or the Hooks page of the Codex app's settings. It also says to trust them again after the hook commands change, because Codex skips a changed hook until then.
- `docs/SCHEMA.md` lists the product note statuses: `captured` while follow-ups are open, `resolved` once they ship.
